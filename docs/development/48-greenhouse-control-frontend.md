# 温室控制页面与前端接入

2026-11-22。用户工作台新增 `/greenhouse-control`，位于温室设计与 AgriSeek 之间；普通用户和管理员均使用本人方案。沿用实时模式的标题栏、深蓝底色、青色边框和用户导航，采用两列设备区、整行 AI 计划区和任务区；内容超过一屏时在工作区滚动。

## 使用流程

1. 选择温室设计中已经保存的棚室；尚无方案时进入温室设计保存。已有方案但未配置控制时，点击“初始化模拟设备”。进入页面只读状态，不自动初始化或生成计划。
2. 左侧按保存的种植带、种植行和喷头绘制布局，滴灌、喷灌、通风、补光符号可筛选。通风和补光位置是示意，未保存实际布线或灯位；A/B 仍是虚拟控制组。
3. 右侧四类设备卡选择已有控制单元，设置运行时长、风速或补光亮度，再启动/停止。齿轮窗口支持改名、分组和停用；尚无控制单元时可新增。运行时长、状态与累计时长取后端，不伪造实测效果。
4. 新建单次/每天任务；任务保存在服务端。编辑、启停和软删除使用后端版本。单次输入明确按北京时间转换为带时区的 ISO 时刻，每天任务固定 Asia/Shanghai。
5. AgriSeek 模块选择生长阶段、计划范围，可选用已存在且地点、尺寸与时间匹配的当前监测快照。没有匹配数据时仍可做配置条件分析，不自动重新查询天气或构场。后端会再次核验快照。
6. 生成后显示动作、执行延迟、参数和依据；编辑后先保存草案，再勾选动作并确认建任务。计划草案自动持久化，确认不会生成普通聊天记录；确认后的任务标记 AgriSeek 来源。
7. 停止全部同时暂停任务；恢复控制不自动恢复旧任务。设计版本改变时显示重新绑定入口，绑定后需要核对设备再显式恢复。

## 结构与状态恢复

API 类型与请求在 `frontend/src/api/greenhouseControl.ts`，格式化工具在 `greenhouse/control.ts`。页面拆成设备卡、布局、计划面板和编辑窗口，避免混入实时监测或温室设计原页面。

`useGreenhouseControl` 管理当前方案、状态、任务、计划与记录。约每四秒读取服务端状态；离页销毁轮询，返回后读取已持久化计划，不重新提交生成。后台网页暂停轮询不影响后端调度。方案选择按账号保存在会话存储；身份变化清空数据、编辑窗口与待提交上下文。较慢的旧棚室响应不写入新棚室，后端返回的设计 ID 也须与选择一致。

写操作统一串行，生成和创建等请求在提交结果未确认时保留相同请求键，避免直接点重试造成重复。服务端仍是幂等和版本校验的最终依据。API 错误直接显示；404 未配置与其他服务失败分开处理，不把断线显示成“没有棚室”。

计划显示固定快照和原始气象/光照时刻，允许展开查看。编辑区、动作表和依据区都有滚动边界；不会因长回答无限展开。设备状态、设计版本、任务变化或过期后，旧计划禁止确认。界面不声称室外光照是冠层实测，也不模拟风机动作后的温度下降。

操作记录与告警分别请求后端最近 30 条；告警过滤发生在后端，避免普通操作淹没更早的调度异常。当前告警是软件调度状态，不是现场传感器或硬件故障检测。

## 初始化 HTTP 500 的修复与真实页面补验（2026-11-22）

实际登录页面初始化失败，同时后台定时调度持续报空指针。根因是 `ControlStore` 的 `@Repository` 触发 Spring 异常转换代理：代理对象与构造初始化的目标对象分离，业务代码直接访问代理的 `jdbc/mapper` 字段会得到 null。此前直接 new 组件的 H2 测试，以及模拟 HTTP 的浏览器验收，没有覆盖真实 Spring 代理；健康检查与匿名 401 也不能证明此业务链路正常。

现将内部依赖字段私有化，业务服务和计划服务全部通过公共实例方法访问目标对象，保留 Repository 异常转换和原有事务，不用取消代理来掩盖问题。`ControlSpringContextTest` 显式开启 Repository CGLIB 及事务代理，通过真实 Controller/MockMvc 和 H2 执行初始化、重复初始化、读取、设备指令、保存任务、计划生成和调度。新增四项测试先复现相同空指针，修复后通过；本轮共 45 项相关 Java 回归通过，打包通过。

已切换本机至 `.local/releases/20261122-control-store-proxy` 并更新启动指针，无新增数据库迁移。使用用户已登录的实际浏览器页面，为当前选中的“人参棚01”成功完成初始化，真实接口返回 HTTP 200，四类模拟设备均显示关闭状态。没有启动设备、创建用户任务或调用真实 AI/天气；新运行日志中控制调度错误为零。

实际页面截图为 `.local/greenhouse-control/initialization-fixed.jpg`，核验摘要为 `proxy-fixed-verification.json`，原启动指针为 `proxy-previous-current-release.json`。这次真实页面核验覆盖本机 MySQL 初始化链路，替代此前仅模拟该链路的验收结论；不扩展为真实设备或模型建议质量验证。
