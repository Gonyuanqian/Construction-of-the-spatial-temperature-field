## 1. 目的与当前完成范围

为“在 A 上训练的固定模型，应用到后续 B、C 时段构建空间温度场”准备数据。
本阶段生成三个兼容现有 XLSX 数据结构的子集、划分规则、来源摘要和数据核对记录。
尚未增加冻结模型评估、空间测点留出、评分接口或前端数据组选择，也未替换默认训练工作区、现有实时源和模型库。

当前数据来自同一采集批次，划分可用于后续跨时段实验；不代表跨地点、跨棚体结构或跨季节的独立采集数据。

## 4. 本次处理

1. 在完整源时间轴上调用现有 `repair_axis`，修复 5 处已知的多移 8 小时时间戳。没有排序、删重或重排测量值。
2. 将修复时间写入主表及质量表，再同步按时间行切分。
3. 主表与质量表均保留原顺序的 52 列，包含全部 24 路温度、24 路湿度、3 个气象变量和时间字段。
4. 测量数值及质量标记逐单元格保留，没有新增插值、平滑、归一化或补值。测点字典和字段说明保持原内容。
5. “处理说明”更新为当前子集时间范围和计数，补充实验用途及原文件摘要；源文件的时间范围和汇总另列保存，防止混淆。
6. 原生 Excel 数据表范围随行数缩短，日期保存为可排序的 Excel 日期值。

“测点字典”中若有补值等累计统计，其口径仍属于完整源数据；当前子集统计以 `manifest.json` 为准。

## 5. 质量标记与评估限制

源文件在本次划分前已经完成线性时间对齐。

| 温度单元格标记 | A | B | C |
| --- | ---: | ---: | ---: |
| 0：原始时刻精确命中 | 227 | 0 | 0 |
| 1：常规线性时间对齐 | 13,523 | 6,912 | 10,656 |
| 2：个别缺测补值 | 74 | 0 | 0 |
| 9：长缺口未补 | 0 | 0 | 0 |

上表只统计 24 路棚内温度，不包含湿度或背景变量。
B、C 没有标记 0 的温度值，后续误差应表述为“相对于已对齐序列的重建误差”，不能声称已经验证了独立原始实测温度误差。

缺少原始采样文件及插值支撑点，当前无法核实原有插值是否跨越 A/B/C 切分边界。
仅按文件时间分开不等于已经排除这类预处理信息交叉。若需严格独立的原始观测验证，应取得原始数据，先划分再分别处理，或另行采集测试数据。

## 6. 后续使用协议

1. A 可以上传训练页面；新实验仅用 A 训练，并记录生成模型与此划分版本的关联。
2. B 用于冻结模型的跨时段验证。如果依据 B 的结果调整模型或选参，B 就是开发验证集，C 继续预留最终评分。
3. C 不参与训练、特征选择、修正参数标定或阈值调整。
4. 完整模型包含同帧 IDW 残差修正；后续评分目标测点必须从该帧修正输入中排除。本次完整保留测点，没有创建空间留出实验。
5. 当前角色限制是实验协议，现有上传 API 不读取或强制执行这些限制；不要把 B/C 上传后点击训练。
6. 当前训练页面仍使用固定时间留出切点 `2026-07-27 12:00:00`；A 全部位于该切点前。该页面不能替代完整读取 B/C 的冻结评估入口。
7. 当前实时源生成脚本也是固定切点，不应直接拿单独 A/B/C 文件调用它来准备本实验。后续评估应明确指定 A 模型与目标子集。
8. 既有保存模型曾使用不同数据范围；本次划分不会使这些模型自动成为合格的 A 训练模型。
