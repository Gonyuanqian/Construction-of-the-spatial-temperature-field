# 不同尺寸棚体的构场验证

更新：2026-11-12。

## 本轮结论

实验性几何映射能够生成同类拱形的不同尺寸估算场，边界、网格、查询和现有 Three.js 渲染均通过检查。模型并未学习尺寸对通风/热交换的影响，当前没有跨尺寸温度精度的实测证据。正式发布能力仍为 reference_only，本轮没有放开用户端的尺寸限制、替换模型或修改业务数据库。

## 方法与限制

冻结上一轮独立棚训练得到的单时刻 G 与 F，使用其尾部留出时段的三个外部气象时刻。G 仍产生八个虚拟点。新模块 `tfield.geometry_transfer` 按 x/W、z/H 将参考横截面映射到目标尺寸，再沿长度复制同一横截面。

参考尺寸为 6×2.1×1.3017 m。参考拱形经独立宽高比例缩放，屋面可能成为非圆弧的同类归一化轮廓，不支持任意棚型。函数要求显式启用参考映射与纵向均匀假设。尺寸须正且有限，网格在分配前检查每轴及总值数上限；这些是工程限制，不是经过验证的模型适用区间。

几何是请求级对象，不改全局常量和训练成品。渲染载荷的棚壳中心仅用于放置几何，实际测量横截面的 y 位置仍为 null；所有生成片均标记为非实测，不在虚构纵向位置画实测点。借用旧载荷的 max_measured_z/stripes 表达原测点相对高度覆盖，不能理解为目标尺寸已有实测。

相同相对坐标在不同尺寸中得到相同温度，是这个方法的数学性质。本轮逐网格对照确认最大差值为 0；它是实现一致性检查，不是“预测误差为零”。当前 G/F 不含长宽高输入，长度方向的梯度始终为零。要学习尺寸改变导致的真实温差，需要不同尺寸的训练/验证数据。

## 已完成的检查

- 八个尺寸：6×2.1×1.3017、3×1.05×0.65085、12×2.1×1.3017、8×3×1.8、6×4.2×2.6034、6×2.1×2.2、30×3×2、60×6×3 m。
- 三个外部气象时刻，检查网格端点、拱外 NaN、拱内有限值、相对坐标一致性和虚拟来源点复现。
- 坐标查询复用现有三线性插值函数；拱外返回 outside，超过原测点相对高度覆盖返回 unmeasured，缺失角点不补数。
- 现有 VolumeScene/volumeMaterial：八种切片渲染与两种立体体绘制，画布不超出容器，无脚本/着色器/资源错误，无业务 API 或收费天气请求。
- 数值相关测试 31 项通过，其中几何模块独立测试 22 项；原 G/F 成品的 SHA-256 在计算前后不变。

## 复现与归档

```powershell
D:/python/python.exe -X utf8 backend/scripts/verify_geometry_transfer.py --reference outputs/model-evaluation-independent-houses-20261111-final --output outputs/model-evaluation-geometry-transfer-repeat
```

目标目录必须不存在。完整实际结果在 `outputs/model-evaluation-geometry-transfer-20261112-final/`：输入摘要、验证 JSON、逐案例 NPZ、现有场景兼容载荷、案例 CSV、图集、浏览器截图、浏览器检查记录和过程日志。数值原型位于独立模块，没有挂载正式 HTTP 路由。

本机开发预览为 `frontend/.local/geometry-transfer-preview.html`，可选尺寸并旋转/缩放，也可切换切片和立体体绘制。它读取固定实验载荷，不调用气象 API，不是正式实时监测功能。浏览器重放脚本位于 `.local/geometry-transfer/browser-check.mjs`。

## 尚缺的精度验证

需要不同尺寸棚体的真实温度与外部气象；若要预测沿长度的变化，还需棚内多个真实纵向截面。应以整棚和整尺寸留出评估，把当前参考映射作为基线，与加入真实结构条件的模型比较。现有三棚同尺寸、单横截面数据不能完成这一步，也不能用缩放生成的虚拟标签充当验证真值。
