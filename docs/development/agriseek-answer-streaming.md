# AgriSeek 正文流式输出与请求恢复

更新：2026-11-23。

## 上游核对

重新查阅 DeepSeek Harness 当前的 [LLM 流式协议](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/llm-streaming.zh.md)、[Conversation 组装](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/conversation.zh.md)和 [Agent 核心循环](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.zh.md)。

其内容块区分正文、推理和工具；客户端按会话与稳定身份组装实时片段和持久消息。提供方尝试与成功提交不同，失败尝试不执行工具副作用，恢复策略受限。这些是协议与生命周期设计，不是强迫模型输出固定思维模板。AgriSeek 参考这些边界改进现有 Python/Java/Vue 链路，没有引入完整 DSH 运行时。

## 本地发现

最近抽取的25条会话状态为9条 answered、4条 partial、12条 failed；这是局部样本，不代表总体失败率。失败包括服务连接、墙钟预算、重复审核、格式和旧的流大小限制。原来已经存在提供方 SSE 和会话 SSE，但收集器只上传长度进度，正文须等审核完才显示。

## 本次改造

- 主回答的公开 content 与 finish_answer 中的 claim.text，在提供方流到达时产生正文预览。设计检验的主生成请求也明确开启预览；需求规划、格式整理与审核请求不输出预览。
- JSON 只提取可读 text 字段，支持跨片段字符串转义；不向页面发送整段工具参数或 reasoning_content。原生推理继续仅在服务端内存续接。
- 新增 answer/update 事件，携带轮次、尝试代次和累计正文。约每200ms发布一次，正文最多20000字符，末尾再同步最后一段。累计快照避免重复追加与漏字，新的尝试替换旧尝试；旧代次和终态后的迟到片段不覆盖当前内容。
- 最新正文同时写入运行快照，刷新、轮询降级和 SSE 游标续接均可恢复。取消、断流或失败保留已收到的未核验草稿；草稿不进入正式回答或多轮事实历史。
- 页面明确标注“正在生成 · 内容待核验”或“生成未完成 · 以下为未核验草稿”；审核通过的正式结果替换预览。工具调用仍必须等完整参数和正确流终态后执行。
- 阅读位置靠近底部时，正文更新自动跟随；用户向上翻阅时保持阅读位置。
- 知识与能力问题首份候选通过后，对同一候选再进行一次独立审核，免去为了凑两轮而重新生成正文。仍要求两次核验，现场查询保持原有约束；能力接口分别报告 min_cycles=1、min_reviews=2、max_cycles=6。
- 连接异常与429、500、502、503、504最多重试一次，间隔约500ms且受总预算与取消检查约束；401等配置/鉴权错误不重复请求。重试不提前执行未完成工具。

这能减少额外模型请求并保留可见进度；上游网络中断、额度或鉴权问题仍可能导致失败，流式输出本身不保证服务成功。

## 验证

新增覆盖：未闭合JSON字符串预览、完整响应前收到正文、断流保留、原生推理不泄漏、事件重放、旧尝试拒绝、取消保护、临时HTTP重试和401不重试。既有两次独立审核检查继续生效。相关后端回归及设计检验、前端事件组装与页面测试分别执行，构建包含Vue类型检查。

真实DeepSeek使用公开农业通识问题、独立临时数据库，不发送用户棚内观测：首段正文4.719秒，最终回答19.000秒，10个正文事件，4次模型请求、2次审核，状态answered。报告 `.local/assistant/answer-stream-live.json`。耗时为单次实测，不代表稳定延迟保证。

回归结果：相关后端155项（其中旧循环次数断言已按两次独立审核更新并重测），设计检验17项，前端33项通过。Vue类型检查、前端构建和Java打包通过。
