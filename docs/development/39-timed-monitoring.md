# 定时监测

更新：2026-11-11。

## 用户操作

实时监测气象条中，在地区选择按钮右侧增加“定时监测”。点击打开设置浮层，选择每 5、15、30、60 分钟更新，默认 15 分钟。未选地点时不能开启。开启立即查询气象并构场一次，此后从每次任务开始时计算下一截止时间；修改间隔从修改时重新计时。浮层显示运行状态、下次更新时间、错误与暂停入口；右侧手动“重新构场”保留。

这是浏览器页面拥有的调度，不是服务端后台任务。离开实时监测页面或标签页不可见时暂缓新请求，返回后若已到期只补一次，不回放错过的每个时间点。已发起的请求可以正常完成。暂停、登出、账号变化、卸载页面均取消后续调度；刷新页面默认关闭。只在 localStorage 按账号保存间隔偏好，不保存开启状态或凭据。

切换地点沿用现有“确认地点立即构场”流程，并重置下一次定时截止时间。原地点的查询或构场回执仍由已有 generation/source_fingerprint 检查丢弃。

## 调用链与并发

`useTimedMonitoring` 只负责时间、页面可见性和任务状态，接收异步 run 回调。LiveView 的回调执行 `refreshDashboard`：查询气象 → 等待 `useAutomaticField.settled()` 完成 G/F 构场 → 读取新会话的帧和体网格摘要；三维模块随会话切换读取新的体网格。

完整查询/构场期间视为忙碌；定时不会叠加另一个构场。截止时间遇到手动构场或长请求，只留下一个待执行更新，完成后接续。请求失败不立即重试，在下个间隔重试并在设置面板显示原因。暂停不撤销已经交给后端的任务。极长任务跨过多个间隔时只补一次。

`TimedMonitoringControl.vue` 提供带时钟图标的按钮、间隔选择、开启/暂停与状态。支持 Escape、外部点击关闭与焦点回到触发按钮；颜色和圆角使用现有主题令牌，不改变其余大屏模块。

## 数据和接口口径

每次复用 `POST /api/live/weather/query` → `POST /api/live/weather/construct`，每次调用仍是一个独立的 single_shot 保存快照，无数据库或接口迁移。查询凭据由后端持有并绑定账号。G/F 模型、照度换算、最近预报近似规则不变。气象缓存仍按服务端有效期执行，选择 5 分钟不保证上游每 5 分钟发布新数据；不绕过缓存，也不将获取时间改成源数据时间。

模型构场完成后，三维网格读取与渲染仍有独立耗时；调度等待查询和构场保存完成，不等待 GPU 动画。系统时钟、温湿度实况时刻、光照预报时刻和构场时间继续分别保留。

## 验证

调度器使用假时钟覆盖默认关闭、开启立即更新、精确间隔、修改间隔、暂停、长任务合并、手动忙碌等待、页面/标签页暂缓、地点变化、账号隔离、卸载与失败重试。构场 settled 单测验证必须等待构场响应；页面集成测试验证开启与定时触发均依次查询/构场，气象条随结果更新，暂停后仅手动构场触发请求。浏览器检查布局、按钮相对位置和浮层交互，不额外调用收费气象 API。
