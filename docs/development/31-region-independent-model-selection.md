# 取消地区与模型的绑定

更新：2026-11-06。

## 模型与气象来源分开

F/G 训练算法、特征组和已训练成品没有行政区划特征，本次不重新训练或改写原成绩。移除的是业务层“根据省市区县挑选棚体档案，再间接选择模型”的限制。

棚体档案现在维护名称、结构、长宽高、启用状态及已发布的 G/F 组合。管理页面移除省市区县、位置说明、地区筛选和地区匹配规则。省市区县仍属于气象观测，用于采集来源、页面显示、历史追溯及区分独立的气象时间序列，不影响模型选择。

## 选择规则

- 用户侧读取全部启用棚体配置，不要求配置中有省市。
- 仅有一份启用配置时可自动选用；存在多份时必须明确选择 `greenhouse_id`，不按地区、创建时间或某个成绩任取。
- 仍验证模型已发布、档案启用、棚型及尺寸与冻结 F 兼容。取消地区绑定不等于放开几何缩放或已经验证跨地区精度。
- 更换气象城市、区县或导入 CSV 不会切换所选棚体及模型。提交时服务端再次验证该配置与版本，防止计算期间改绑模型。

## 接口

原 `/api/user/weather/match`、`/api/live/match` 保留地址，改为棚体配置解析。请求为 `{greenhouse_id}`，或者无编号时按上述单配置规则处理。原请求中的 `location` 不参与解析。返回 `{archive,selection_mode: explicit 或 single}`，不再返回市级/区县匹配等级。

构场请求示例：

```json
{
  "greenhouse_id": "管理员保存的棚体配置UUID",
  "location": {"province_code":"220000","city_code":"220200"},
  "timestamp":"2026-11-06T12:00:00+08:00",
  "bg_temp":25.0,
  "bg_light":1000.0,
  "bg_rh":60.0
}
```

编号仅引用服务端审核的棚体配置，不接受用户指定模型编号或文件路径。`full` 仍要求湿度；`two` 仍由 G 估计 F 所需湿度。气象所在地仍用现有地区字典校验，地区字典的覆盖范围与模型选用是两件事。

## 数据兼容

无需数据库结构迁移，不修改既有迁移脚本。当前档案响应隐藏废弃地理字段，新档案不写地区。旧记录的地区列继续留在库中以保留原数据；显式编辑保存该配置时清空废弃的省市区县绑定，避免旧生成列唯一索引妨碍多份配置并存。该行为已在保留旧索引的隔离库中验证。

已保存的 `weather_frame.location_json`、`archive_snapshot_json` 和温度场文件不改写。当前账号、棚体配置、气象来源地区、部署版本和配置快照继续隔离一小时历史。新格式档案快照可能令旧连续历史冷启动，但不会将不同城市的天气串接，也不会重新计算历史场。

原模型名称、训练数据来源和历史地理记录不批量改名或删除。以前名称中含市名的记录仍可在其他气象来源地区使用，市名不再充当适用条件。

## 验证

- 前端：不填写地区创建/修改棚体；模型发布与绑定保留；多配置选择；更换气象城市不重新选模型；CSV、零值、旧异步回执与输入方案兼容。
- Java 隔离库：相同时间、不同城市调用同一所选模型，保留独立观测及账号历史；无地区配置可启用；多配置必须明确；停用、尺寸不符和并发变更仍拒绝；原地区索引不阻止编辑后启用。
- Python 训练、模型格式及推断算法不变。
