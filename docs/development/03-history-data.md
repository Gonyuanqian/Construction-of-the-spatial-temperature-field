# 历史数据页面开发交接

更新日期：2026-10-18。导航预留路径：`/history`。当前尚无专用历史页面与历史存储服务。

开发前先阅读[共同设计与开发约定](00-shared-ui-guidelines.md)。本文建议从可查询的数据来源出发，逐步形成回看与追溯能力；数据库结构、筛选维度、回放形式和首期功能可由团队讨论调整。

## 1. 页面目标与分工

用户能够选择来源和时间，找到过去发生的温度变化，查看某一时刻的读数或温度场，并理解记录是当时保存的结果还是后来重新计算的结果。

实时监测负责当前展示，助手负责自然语言查询与解释。历史页以时间筛选、趋势、记录和追溯为主；需要时展开三维或断面，不要求首屏重复实时页的全部面板。

## 2. 当前有哪些数据、缺什么能力

| 现有基础 | 可以复用的部分 | 当前限制 |
| --- | --- | --- |
| 实时演示源 `configs/live/` | 固定训练段与回放段，可用于阶段性数据浏览 | 游标和管线状态在内存，尚无运行记录归档 |
| 训练模式数据集 | `/api/dataset/timeseries` 提供现有数据集的时序，`/preview` 提供预览 | 属于当前导入数据集，不能当成实时监测历史 |
| `/field` 页面 | 既有时间游标、断面与三维查看能力 | 面向训练数据管线，不等同于独立的历史记录服务 |
| `/api/field/curve` | 既有点位曲线能力 | 有自己的时间轴和约束口径，需要读响应说明 |
| MySQL 模型库 | 现有连接和模型版本可作为后续设计参考 | 当前模型表不是监测历史表 |

目前没有 `/api/history/*`、归档写入任务、按来源与时间查询记录、历史分页或长期保存的体网格快照。实现页面时要把新增后端工作列入计划。

现有实时接口只允许读取已经走到的帧，而且构场可能按需补入实时管线。不能为了“查看未来某帧”调用 `start/next`，也不能把推进当前实时源当成历史查询的实现。

## 3. 首期范围的可选路线

可根据交付时间选择起点，先明确页面到底在展示哪类数据。

| 路线 | 适用条件 | 交付时说明 |
| --- | --- | --- |
| 固定数据浏览 | 先用现有文件实现可用页面 | 显示“演示数据”或明确的数据集来源，回看使用独立管线，不承诺保存过往运行 |
| 监测记录归档 | 需要查看服务重启前的监测结果 | 先做持久化和按时间查询，再接趋势、记录和回放 |
| 混合来源 | 同时需要上传数据集和监测档案 | 显式选择来源，标明时间范围和计算方式，不默认拼接成连续历史 |

建议先交付单一来源的“筛选、趋势、选择记录、查看详情”闭环。趋势比较、导出、三维连续回放和智能总结作为后续候选。

## 4. 页面布局与统一风格

建议采用紧凑筛选区、概览、主图和记录详情的层级：

```text
共同顶栏、模式开关与左导航
┌ 主内容区 ────────────────────────────────────────────────┐
│ 历史数据：来源 / 时间范围 / 测点或区域 / 查询              │
│ 记录覆盖情况与可选统计卡                                  │
├ 温度趋势主图 ────────────────────────┬ 选中记录详情，可选 ┤
│ 时间轴、测点或均温曲线                │ 时刻、来源、模型   │
│                                      │ 断面或三维预览     │
├ 记录列表与分页 ───────────────────────┴────────────────────┤
└───────────────────────────────────────────────────────────┘
```

布局比例、详情使用右栏还是抽屉、图表与列表是否同时展示均可调整。首期信息较少时保持简洁，不用大量空白指标卡填充版面。

页面应沿用共同的深蓝底、卡片、线框图标、按钮与字体。筛选器的边框和输入背景使用现有令牌；表头、单位、日期和数值对齐统一。趋势图复用 `EChart.vue` 与 `readPalette()`，系列颜色在共同规则中定义，避免每位成员另选配色。

历史的主横轴是时间，沿棚均温的横轴是空间；标题与单位需要明确。对多个时间点的温度场进行视觉比较时，讨论并标明共用色标范围，避免相同颜色对应不同温度。

长记录允许在明确的内容区滚动；筛选状态和当前来源应容易找到。是否固定筛选条或表头由实际布局决定，避免与外壳滚动嵌套冲突。

## 5. 功能候选

| 功能 | 建议行为 | 待讨论部分 |
| --- | --- | --- |
| 来源与时间筛选 | 先显示可用时间范围，查询结果可回到同样条件 | 快捷时间范围、默认来源与最大跨度 |
| 温度趋势 | 选择原始测点、规定区域均温或已归档摘要 | 首期支持哪些维度、降采样策略 |
| 记录列表 | 显示数据时间、来源、数据状态及可用操作 | 列字段、分页方式和默认排序 |
| 单时刻详情 | 原始读数、摘要、模型来源、必要的断面或三维 | 详情粒度和是否默认加载三维 |
| 历史回放 | 使用独立历史游标和清楚的播放状态 | 倍速、跳过空档、需要缓存多少帧 |
| 多时刻或区域比较 | 显示同一口径下的温度差异 | 比较对象和统一色标策略 |
| 导出与报告 | 记录筛选条件、单位和计算来源 | 首期是否需要、CSV 或其他形式 |
| 助手联动 | 将选中记录或时段交给助手解释 | 联动入口与会话上下文形式 |

不需要为了首屏展示同时实现全部功能。图表优先回答“何时变化、变化多少、哪里变化”，再按真实需求增加更深分析。

## 6. 数据归档与可追溯设计建议

如果本期选择监测归档路线，应先设计保存和读取规则。可以沿用现有数据库技术，也可以评估独立存储；下面按信息职责描述，不固定表名和字段名。

| 信息对象 | 建议保存内容 | 原因 |
| --- | --- | --- |
| 来源与运行批次 | 来源类型、标识、数据版本、启动或运行批次 | 不同数据源和不同运行不能混为同一段历史 |
| 原始观测 | 采样时间、采集时间（如有）、测点与读数、数据质量 | 保留重建输入，区分迟到、缺测与采样时间 |
| 重建描述 | 实际模型或成品版本、几何版本、约束、网格和统计策略 | 说明当时结果如何得到 |
| 摘要与快照 | 均值、其他已定义统计、可选体网格、生成时间和关联记录 | 支持快速列表和原结果查看 |

是否保存每帧全量体网格可以比较两种方案：保存快照便于直接还原但增加空间；保存原始观测与计算依赖可减少重复，但需要长期保留模型成品和计算版本。也可采用摘要常存、重点帧快照、其余按需重算的混合方案。选型前估算实际帧率、数据量和查询速度。

共同的数据要求：

- 原记录查看和重新计算清楚区分。使用新模型计算旧时刻时标明模型和生成时间，不覆盖原记录的身份。
- 原模型或输入已不可用时，明确无法复现。不要静默换成当前模型，再称为当时保存的结果。
- 定义稳定记录标识与幂等写入规则；重复请求同一批次、同一采样记录不无限增加重复数据。
- 缺失、异常、无定义和有效读数保留各自语义，不把空值写成零，也不由前端补齐成连续曲线。
- 明确时间范围边界、时区、排序、同一时间多个来源和迟到记录的处理方式。当前无时区时间字段迁移时需要统一约定。
- 保存统计的采样策略。例如实时摘要采用稀采样，之后高分辨率重算得到不同均值应能解释。
- 保存期限、归档写入时机和失败重试方式由团队结合部署目标确定，不把读取页面作为唯一写入触发点。

## 7. 接口讨论草案

以下名称均为新增能力示例，目前未实现。团队可按所选路线合并或拆分接口，确定后统一维护前端类型和 OpenAPI。

| 候选接口 | 职责 |
| --- | --- |
| `GET /api/history/sources` | 返回可查询来源、覆盖时间范围及可用能力 |
| `GET /api/history/records` | 按来源、时间、点位等筛选记录，提供分页 |
| `GET /api/history/series` | 返回规定采样或聚合策略下的时序数据 |
| `GET /api/history/records/{record_id}` | 返回记录详情、原始读数与计算来源 |
| `GET /api/history/records/{record_id}/volume` | 若可用，读取或获取已说明口径的体网格 |

如果需要用另一模型重算，建议显式提交计算任务或明确的重算请求，与“读取当时记录”区分。仅查询历史不能改变实时游标、当前模型或训练数据集。

接口至少需对齐：

1. 来源标识、时间范围边界和可选测点或区域。
2. 返回时刻、记录或快照标识、单位、原始/重算标记、实际模型和统计设置。
3. 列表分页与稳定排序，时序请求的最大点数和聚合方式。
4. 查询为空、来源不可用、记录不存在、原模型不可用和计算失败的明确返回。
5. 若返回降采样数据，同时报告分辨率、样本覆盖或聚合说明，不能把每个桶的值伪装成原始采样。

现有 `/api/dataset/timeseries` 没有通用历史查询条件，不应仅在前端增加筛选控件便声称后端已支持跨来源历史查询。

## 8. 回放、图表与性能

- 使用独立的历史选择时间或记录标识；历史播放速度只影响本页，不修改 `LiveSource`。
- 拖动时间轴时防抖并处理旧响应；点击停止、切换来源或离页时停止本页定时器和请求。
- 大时间范围先取聚合趋势，再按需读取详细记录。列表分页，三维按需加载，不在进入页面时构建全部帧。
- 缓存需要区分来源、记录、模型、几何和网格设置，并有容量限制；同一时间戳不意味着是同一个结果。
- 3D、断面和摘要复用当前渲染与数据装配能力。需要适配历史数据入口时，通过接口或数据提供层扩展，不把历史记录号误塞进实时帧号。
- 多时刻比较明确统计区间与色标；缺测保留断点，播放经过空档时说明是在跳过记录还是时间本身不连续。
- 助手联动携带选中的历史记录，回答仍基于该记录。来源被移除或记录不可访问时呈现可理解的提示。

## 9. 建议实施顺序与状态设计

1. 先明确首期来源，以及是否承诺服务重启后仍可查询旧记录。
2. 按所选路线提供真实的来源、记录列表和时序查询，完成一条小范围查询闭环。
3. 在共同外壳下完成筛选、趋势和单条详情，建立真实数据的视觉基线。
4. 再按需求加入历史回放、比较、导出和助手联动。

状态应包括首次选择来源、查询中、无来源、所选范围无记录、存在缺测、查询失败、详细场景构建中、原记录不可复现等。加载下一页或某个详情时，保留其他已成功内容；空结果不与服务故障混为一谈。

## 10. 建议验收与接手代码

- 选择来源与范围，列表、趋势和详情反映同一查询条件；直接刷新与返回操作能恢复必要筛选。
- 页面与实时页、助手页在导航、主题、卡片、字号、控件和图表文字上统一。
- 若承诺持久化，重启后可读到同一记录和来源；若仅浏览文件数据，界面明确说明数据类型。
- 同时打开历史页和实时监测，历史查询、拖动和播放均不改变实时源状态或模型选择。
- 原始读数与重建数据标识清楚；原记录与重算结果可区分；不存在的记录不替换为当前帧。
- 空时间段、边界时刻、重复时间、缺测、长时间范围与分页稳定排序有覆盖。
- 数值与后端同一口径结果相符，降采样和不同网格的差异有出处；缺测处曲线不伪造连续性。
- 自动验证建议关注时间边界、幂等归档、来源隔离、历史读取不推进实时状态、查询并发和关键页面状态；人工操作检查趋势可读性、回放和三维详情。
