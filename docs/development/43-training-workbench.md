# 双页签模型训练工作台

更新：2026-11-14。按确认的两张设计稿实现 `/train`：温度场构建模型与气象映射模型分别训练，均按“选模型 → 参数 → 训练 → 测试评估 → 命名保存”纵向排列，不要求一屏展示全部内容。

## 页面与功能

- 温度场模型：趋势算法可选 XGBoost、随机森林、ExtraTrees、岭回归；残差插值可选 IDW、RBF。参数随模型切换，恢复默认值仅作用于对应参数组。普通克里金、LightGBM 尚未接入，因此不提供可点击的虚假选项。
- 气象映射：独立选择上述映射算法，仅用当前外部温湿光及时间派生特征预测单棚 8 点。三座独立棚作为分组样本，不把它们视作一座 18 m 棚；此工作台生成单时刻版 G，原来的历史版及联合训练成品保留。
- 手动模式直接使用页面参数。自动模式按逗号分隔的候选值做笛卡尔搜索，留空参数固定；最多 16 组，单参数最多 6 个候选。最优参数回填后可核对、命名和保存。
- 后端生成真实的测试集 R²、MAE、RMSE、逐点成绩及绘图数据。构场页显示测试时段的平均残差空间散点，悬停可查看对应 MAE；气象映射页按棚体、测点显示实测与预测时间曲线。主指标统计全部测试测点，不随单条曲线筛选而改变。
- 训练工作区由登录后的应用外壳持有。切页继续轮询；重进后恢复进度与结果。两个页签分开保存参数、任务和结果；历史报告迟到不能覆盖用户新选择的页签。修改参数后保留上次结果并标明来源，重新训练前不能把旧成品保存为新参数结果。
- 手机宽度下训练页导航与参数组纵向排列；图表随容器调整，桌面内容正常纵向滚动。

## 训练与评估口径

由 `tfield.training_workbench` 实现新工作台，原 `independent_training` 联合训练和旧版训练协议继续兼容。

1. 数据严格按时间切分，前 80% 为训练时段，尾部 20% 为最终测试集。测试标签不参与候选选择，最终成品也不使用测试时段重新拟合。
2. F 自动选参仅用训练时段 A 位置留点误差。每次把目标位置在三座棚中的全部标签从趋势拟合中移除，并从每座棚的插值来源中移除。参数固定后，对测试时段全部 8 个位置分别作同样的留点评估，报告三棚汇总成绩。**其余 7 点是同期真实测点**，因此这是有测点来源的重建误差，不能与仅输入外部气象的在线精度混为一谈。
3. G 自动选参在前段训练时段内部再次按时间留出 20% 做选择，选定后用完整前段重新拟合；最终尾部测试集只用于一次报告。输出 8 点，分别与三棚对应的真实标签比较。
4. 残差图使用 `实测 − 预测` 的测试时段均值；均值可能抵消正负误差，因此同时提供 MAE、RMSE 和逐点明细。G 曲线最多均匀抽取 180 个时刻用于显示，指标仍使用全部测试时刻。
5. RBF 为归一化横截面上的线性径向基函数，距离经横向/竖向尺度缩放，平滑系数可调；它修正趋势残差。旧 IDW 的同棚来源策略不变。扩展的 `SectionFieldModel` 默认仍是 IDW，旧冻结 pickle 保持兼容。

以上评估仍不证明纵向、其他棚体尺寸或跨季节精度；模型结构及原型边界沿用独立单棚协议。

## 温差映射与公式对照（2026-11-23）

- 新建 G 任务默认选择 `prediction_target=delta`：拟合每个参考测点的 `T_i - T_out`，推断时加回当前外温后输出 8 点温度，F 接口仍接收温度。可以切换回 `absolute`；旧请求、旧报告和缺少该属性的旧成品按直接预测温度解释。
- 每次工作台 G 训练均报告四项同口径对照：直接外温、逐点温差公式、直接预测温度 G、预测温差 G。公式为 `T_i = T_out + b_i + c_i × light/10000`，仅由训练前段拟合并展示各点系数；光照除以 10000 仅调整尺度，不转换辐射单位。
- 两种 G 沿用本次用户选择的算法和参数；自动搜索仅优化选定预测目标，其他目标不另用最终测试集选参。报告对照统计三棚全部测试测点，不自动根据测试成绩更换保存对象或上线模型。
- 气象输入超出训练范围时仍允许构场，旧保存结果也正常读取；不生成或展示训练范围警告，旧结果中的范围警告在读取时过滤。训练范围仅保留为模型元数据。公式及温差模型也不因此取得冬季适用性。
- 本次真实离线对照沿用 1164 个时刻，前 931 拟合、后 233 测试，共 5592 个测点预测对。ExtraTrees 使用 80 棵树、深度 12、叶节点最少 2、种子 42。外温 MAE=0.6506℃，逐点公式=0.4312℃，直接温度 G=0.3598℃，温差 G=0.2506℃。这是逐测点成绩，不能与先前“24 点算术均温公式”的成绩混用。
- 报告与候选成品在 `.local/temperature-difference-candidates/20261123T030900Z/`。2026-11-23 实时链路将该温差 G 与原冻结 F 组成独立部署目录 `.local/prototype-models/delta-g-20261123/`，由 `TFIELD_PROTOTYPE_MODEL_DIR` 指向；原 `reference/` 保留可回退。上线采用温差 G，逐点线性公式仍作训练对照；动态热平衡公式残差学习尚未实现。
- 针对性验证覆盖温差还原、湿度输出隔离、旧成品兼容、最终测试标签隔离，以及越界输入仍可构场、旧越界结果仍可读取。

### 实时温差 G → F 接入

`backend/scripts/package_delta_prototype.py` 用候选成品重新预测原报告的 233 个测试时刻，将 8 点交给现有 F，并核对测点处重建与 G 输出一致、5592 个预测对的指标与报告相同。不重新训练、不将最终测试标签加入拟合。新包记录 G 摘要、原 F 摘要、源数据摘要及验证报告；旧历史版文件仅保留为非活动成品，当前原型始终使用单时刻 G。

数据流为：外部温湿光和时刻 → G 预测 8 点温差 → 加回当前外温 → F 趋势及同棚残差插值 → 三维网格。接口 `GET /internal/v1/weather/prototype` 返回实际加载模型的 `prediction_target`；保存结果的 summary/provenance 也记录 `delta`。成品引用随新包变化，同一查询不会复用旧模型的缓存构场；旧历史结果按原值读取，页面需要重新构场才能取得新推算。

固定输入 `2026-11-22T02:10:00Z`、湿度 29%、光照 47795，在参考尺寸下，外温 −5℃ 的 8 点均温为 −2.8024℃、构场均温为 −3.1535℃。这是低温输入的响应检查，不是冬季实测精度。完整检查见新包 `acceptance.json`；训练范围不触发拦截或提示。

## 接口与保存

沿用管理员专用 `/api/weather-training` 与现有异步任务机制，Java 继续注入登记数据集快照，不接受客户端文件路径。新任务示例：

```json
{
  "name": "温度场构建模型",
  "spatial_protocol": "independent_house_section_v2",
  "workbench": {
    "target": "field",
    "mode": "manual",
    "algorithm": "xgboost",
    "interpolation": "idw",
    "params": {"n_estimators": 120, "max_depth": 5, "learning_rate": 0.08, "subsample": 0.8, "power": 2, "lx": 0.5, "lz": 0.2},
    "search": {}
  }
}
```

`target=mapping` 为独立 G；参数仅允许所选算法实际支持的键，整数、范围、候选数量均在服务端校验。G 树模型额外支持可调随机种子。新报告 `protocol_version=3`，包含 `training_target`、`selected_params`、`tuning`、`test` 与 `plot`，原报告不改写。

- `POST /api/weather-training/jobs`：带 `Idempotency-Key`，创建异步任务。
- `GET /api/weather-training/jobs/{id}`、`POST .../cancel`：读取和取消；取消在当前拟合结束后的检查点生效。
- `POST /api/weather-training/jobs/{id}/save`：仅接受 `{ "name": "名称" }`，仅已完成的新工作台任务可保存。保存前重新校验成品文件 SHA-256；同一任务同名重试复用，换名重试返回 409。
- `GET /api/weather-training/models`：返回命名保存的单棚成品清单，不依赖当前数据集。普通用户和未登录用户无权访问。

新 F 保存 `field.pkl`，G 保存 `current.pkl`。任务与报告仍位于 `TFIELD_WEATHER_TRAINING_ROOT/<job_id>/`；命名保存信息写入同目录 `state.json` 的 `saved_model`。恢复服务后保留，无须数据库迁移。**该目录需要和 MySQL 一起备份**。模型库新增“单棚训练成品”区，可打开对应训练报告；旧 MySQL 模型记录和原有详情功能保留。

本次没有自动发布或替换运行模型，也未把单棚 pickle 塞入旧 24 点模型接口。现有实时原型继续使用 `TFIELD_PROTOTYPE_MODEL_DIR` 中的可信冻结组合；新成品与实时配置的组合发布、构场页面选择接入需要另行处理。
