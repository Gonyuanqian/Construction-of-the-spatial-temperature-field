# 棚体档案与地区自动匹配

历史记录：2026-11-04；数据库迁移 V6。2026-11-06 起已取消地区与模型的绑定，当前业务规则见 [地区无关的模型选用](31-region-independent-model-selection.md)。下文保留原实现及历史数据格式说明。

## 业务流程

管理员维护共享棚体档案，普通用户不再与棚体逐个绑定。档案包含名称、吉林省市州/区县、位置补充说明、长宽高、固定几何模板、启用状态及已发布 G/F 气象模型配置。账号管理仍控制登录和角色；共享档案不等于共享用户的气象和结果。

用户在实时监测页面选择气象所在地，系统显示匹配档案、尺寸及模型，再由用户输入时间、背景温度、背景光照，按模型需要填写背景湿度。提交时后端再次按地区解析配置，不接受用户直接指定模型、棚内测点或文件路径。没有接入天气提供商，也没有把 IP、浏览器定位或自由文本地名当作可靠行政区划。

## 地区和匹配规则

字典位于 `backend-java/src/main/resources/regions/jilin.json`，由后端统一提供给两个页面。采用省政府[行政区划代码查询](https://zwfw.jl.gov.cn/jlszwfw/gr/xzqhdmcx/index.html)的 6 位代码，2026-11-04 核对；9 个市州、60 个县级行政区。数量另与民政厅[2025 年区划公布](https://mzt.jl.gov.cn/xxgk_2643/zcwj/shfl/202601/t20260126_9406573.html)核对。名称由服务器根据代码生成，不能由客户端伪造；区县须属于所选市州。“市辖区”汇总代码、开发区和乡镇暂不作为独立匹配层级。

1. 省、市必填，区县选填。省目前仅允许吉林省 `220000`。
2. 提供区县时，先查该区县的启用档案，没有时查同市的全市默认档案。
3. 只提供市时，只匹配全市默认档案，不任取该市某一个区县档案。
4. 同一地区可保留多份停用档案，但仅一份启用档案。MySQL 生成列 `active_region` + 唯一索引拦截重复；前端提示先停用原档案或细分区县。
5. 找不到档案返回 404。已命中档案但无已发布模型或尺寸不兼容，匹配预览返回 `ready=false`；构场返回 409，不跳过它偷偷换用市级模型。
6. 管理员停用区县档案后，该区县可重新使用明确配置的全市默认档案。

这是本轮的默认业务规则。如果后续同一地区需要多种棚型，应增加棚型/规格匹配维度或明确的地区默认档案，不可删掉唯一限制后按创建时间任取一行。地区路由建立的是业务适用关系，不能证明模型已具备吉林省不同地理环境的预测泛化能力。

## 尺寸和模型边界

现有 `ginseng_arch_v1` 包仍使用固定坐标与 24 点布局：x 宽 2.1 m、拱顶高 1.3017 m、源平面 y=3/9/15 m、显示范围 y=0–18 m。当前档案的长字段与该 18 m 构场范围比对，不能把它解释为数据已经证明了某座实际棚体的物理长度。三维壳体示意长度滑块仍仅控制显示。

档案可保存其他正尺寸作为待适配资料，但 `ready=false`、不执行推断。需要扩展模型包的几何元数据和坐标映射、验证缩放/跨棚误差后，才能放开尺寸兼容检查。当前没有实现缩放，也不会修改冻结 F 或重新训练以迎合档案尺寸。

## 接口

所有接口均须登录；`/api/admin/**` 仅 ADMIN，`/api/user/**` 允许 USER/ADMIN。

| 方法、路径 | 约定 |
| --- | --- |
| `GET /api/user/regions` | 省、市州、区县及字典来源 |
| `GET /api/admin/greenhouses` | 全部档案，包括停用和待补全旧档案 |
| `POST /api/admin/greenhouses` | 创建档案，字段见下例 |
| `GET/PATCH /api/admin/greenhouses/{id}` | 查询/完整修改档案，PATCH 与创建字段相同 |
| `PUT /api/admin/greenhouses/{id}/weather-model` | `{weather_model_id}`，只接受已发布部署 |
| `GET /api/user/greenhouses` | 共享的已启用、有地区代码的档案，不再按成员筛选 |
| `POST /api/user/weather/match` | `{location}` → `{archive, location, match_level}`，`archive.ready/unavailable_reason` 解释可用性 |
| `POST /api/user/weather` | 地区 + 时间 + 外部气象；自动匹配并返回已保存帧 |
| `GET /api/user/greenhouses/{id}/frames?limit=20&offset=0&region_code=220621` | 当前账号历史，region_code 可选；页面按所选气象地区过滤 |
| `GET /api/user/greenhouses/{id}/frames/{frameId}/field` | 只读取当前账号自己的已保存场，包括档案或模型已停用时 |

## 历史、幂等和并发

- 同一账号 + 档案 + 气象地区为一个流。相同时刻相同输入返回原结果，不同输入 409；不同账号和不同气象地区可在同一时刻独立提交。
- 第一阶段最近 12 条历史仅取当前账号、档案、地区、气象部署和同一档案配置快照的数据。连续 13 帧且每 5 分钟一帧时才使用一小时模型；换地区、配置、模型或断档会冷启动。
- 每帧保存规范化位置和当时档案/模型配置快照；修改档案不重算或改写旧结果。返回值不暴露创建者 ID 或输入摘要。
- 普通用户和管理员预览工作台均只读本账号结果。管理员档案管理权不自动变成读取其他用户气象结果的业务接口。
- 推断在事务外执行。提交事务锁住目录锁、档案和模型，复核位置匹配、配置 revision、发布状态及本流最新记录，防止并发请求或计算期间配置变更写入错误结果。观测写入不再增加档案配置 revision。
- 首版的短事务目录锁会串行化提交确认与档案变更，计算仍在锁外。若未来并发量明显增加，可用地区路由版本、独立流锁替代，保留重检和幂等约束。
