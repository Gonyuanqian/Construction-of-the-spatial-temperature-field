# 实时工作台共同设计与开发约定

更新日期：2026-10-18。适用范围：实时监测、温度场智能助手、历史数据三个页面。

这份文档用于团队交接，以当前工作区代码和已确认的界面调整为基线。功能建议用于启动讨论，页面数量、布局比例、组件命名和接口草案均可随开发调整。已经确认的视觉语言和数据口径需要由三个页面共同维护，避免单页各自演化。

## 1. 阅读入口与约定强度

| 文档 | 负责的问题 |
| --- | --- |
| [实时监测开发文档](01-live-monitoring.md) | 当前温度场的展示、操作与后续优化 |
| [温度场智能助手开发文档](02-temperature-field-assistant.md) | 结合系统数据进行问答、解释与视图联动 |

本文中的“共同约定”是页面间应保持一致的基线；“建议”是可调整方案；“待讨论”表示需要团队结合数据、工期或使用场景决定。功能清单不代表本轮全部实施，也不应直接当成固定排期。

## 3. 共同视觉语言

三个页面属于同一个实时工作台，共用深蓝背景、青色轮廓与强调、亮蓝交互、浅蓝白文字。页面任务允许有不同布局，但切换时系统顶栏、模式开关、导航、卡片、字号和操作状态应保持连贯。

### 3.1 颜色以现有令牌为源头

以下为 `frontend/src/design/tokens.css` 中 `.theme-live` 的当前取值，便于设计人员对照。实现时引用令牌，后续以代码中的统一定义为准。

| 角色 | 令牌 | 当前取值 |
| --- | --- | --- |
| 页面背景 | `--paper` | `#031329` |
| 卡片背景 | `--card` | `#062044` |
| 输入区、次级信息格 | `--card-2` | `#092A50` |
| 顶栏、导航底色 | `--header`、`--nav-tint` | `#041A35` |
| 正文 | `--ink` | `#EAF6FF` |
| 说明文字 | `--ink-muted` | `#8BA9C8` |
| 标题强调 | `--title-ink` | `#DCEEFF` |
| 普通边界、分隔线 | `--steel` | `#22375A` |
| 内容强调 | `--leaf` | `#34D3C4` |
| 选中导航 | `--nav-blue` | `#4C86FF` |
| 主操作、焦点 | `--interact` | `#087EFF` |
| 轮廓高亮 | `--edge` | `#00CFFF` |
| 正常状态 | `--ok` | `#00E6A8` |

- 页面组件不写独立色号；新语义确有需要时在共同令牌中增加，并一起检查三个页面。
- 卡片使用 `Card.vue`。圆角使用 `--radius`，当前为 6px；阴影使用 `--shadow`，局部高亮复用 `--glow-edge` 或 `--glow-lift`。发光集中于边界、选中状态，不铺满每条文本和每个图表。
- 状态必须同时有文字或图标含义，不能仅靠颜色判断。未定义的“高温告警”颜色和阈值由团队统一讨论后补充。
- 数据温度沿用正向 turbo 色标；误差图沿用项目误差色标。温度颜色不直接承担导航、按钮和问答气泡的分类功能。

### 3.2 字体、间距和图标

| 角色 | 现有令牌及基线 |
| --- | --- |
| 中文正文 | `--font-cn`，沿用现有字体回退链，不另加载单页字体 |
| 数字和坐标 | `--font-num`、`.num`，用于需要对齐的数字 |
| 系统标题 | `--size-title`，26px |
| 页面标题、小节标题 | `--size-h` 18px、`--size-h3` 16px |
| 正文、标签、说明 | `--size-body` 15px、`--size-label` 14px、`--size-note` 13px |
| 主要读数 | `--size-readout`，36px；紧凑卡片可复用较小层级 |
| 图表文字 | `--size-chart-axis` 12px、`--size-chart-title` 14px |
| 空间节奏 | `--gap-s/m/l/xl`，当前依次为 8/16/28/44px |

图标复用 `Icon.vue` 和 `design/icons.ts`，保持 24×24 线框、`currentColor` 描边。助手使用已有 `chat`，历史使用 `clock`。新增图标加入同一张路径表，避免混入 emoji、图片图标和另一套粗细不一的图标库。

图表通过 `readPalette()` 读取令牌，统一使用 `EChart.vue`；Three 场景复用现有 `scene/`。坐标轴单位写清，标题由卡片或图表单方承担，避免标题重复、轴标签重叠、裁切和大量空白。空值保留为空，曲线在缺测处断开。

### 3.3 布局统一的是框架与组件，不限制任务布局

共同外壳是系统顶栏、左侧导航上方的模式开关、左导航和主内容区。实时页以温度场画布为重点；助手页以对话和证据为重点；历史页以筛选、趋势和记录为重点。

现有桌面基线为顶栏最小高度 76px、左导航 210px；实时右工具栏为 390px，较窄桌面收至 320px。这些是当前实现参考值，新增页面是否需要右栏、比例如何设置可以调整。共用右栏配置应由外壳统一管理，无内容时不留空白列。

- 新页面不再绘制一套系统顶栏或自己的模式开关。
- 卡片标题、图标、说明、工具按钮的相对位置沿用同一规律；输入框、下拉框、分段切换、空态使用一致的边框和字号。
- 保留 `min-width: 0`、`min-height: 0` 等收缩条件；滚动容器有明确职责，避免整个窗口与内容区同时出现无意义的滚动。
- 实时页保持桌面下三维温度场、环境参数、沿棚均温三块同屏的方向。助手的对话、历史的表格可以滚动，不能把实时页的压缩策略生搬到长内容页面。
- 当前 `App.vue` 在 1440px、1200px 附近调整右栏；`LiveView.vue` 在更窄时调整底部模块。新增断点先检查这些规则，避免每页另外定义一套相互冲突的断点。
- 建议以 1920×1080、1440×900 检查桌面主体验，再检查 1366×768 和约 1200px 宽的可读性。具体支持范围可由团队补定；窄屏下优先保证文字、控件和图表可用。

## 4. 共用外壳接入是新页面的前置工作

当前 `App.vue` 通过 `route.path.startsWith('/live')` 判断实时模式。这同时控制主题、导航、模式开关位置、右栏、数据集空态闸门和 `lastTrainPath`。直接新增 `/assistant`、`/history` 路由会被当成训练页面。

建议在路由 `meta` 中统一声明工作区，例如 `workspace: 'live'`，由外壳消费；也可以使用团队认可的统一路由分组方案。接入时一起处理：

1. 三页均显示实时工作台的主题、导航与模式开关。
2. 实时工作台内切页不覆盖训练模式最后停留路径；是否记住最后一个实时页面可讨论。
3. `NavRail` 激活项与路由匹配；页面真正可用时再启用导航并清理占位说明。
4. 实时页与其余页面的数据源闸门分别按需要判断。静态帮助问答不应被“训练数据集未上传”挡住；历史无记录也应有自己的空态。
5. 右栏和 `#shell-side` 的生命周期明确；当前 `VolumeView` 使用 Teleport，目标必须先存在。切页时清理旧内容，别让历史页出现实时页的相机控件。
6. 训练模式和模型库现有路径、主题与操作保持可用。

可渐进提取共同外壳配置或组件，无需为了三个页面立即引入新状态库。

## 5. 三页共用的数据与交互口径

### 5.1 时间、模型和空间

- 数据时刻来自载荷，和顶栏的本机挂钟分开。当前接口时间多为无时区字符串，不应直接追加 UTC 标志或擅自换算；若统一时区，前后端一起定义。
- 实时帧号 `n`、管线下标 `t_index`、用户看到的时间是三种信息，不互相冒充。现有 1164/144 帧是演示数据的规模，不作为新页面算法常量。
- 模型库“当前选中模型”不必然等于已准备实时管线实际使用的模型。问答和历史追溯需要记录计算时使用的模型版本，不能只读取后来变动的全局选择。
- `x`、`y`、`z` 与既有数据定义一致。`y` 是沿棚位排列的空间轴，默认展示范围 0 至 18m；它不等于单座棚的真实长度。`shellLength` 是示意几何参数，不改变温度场。
- 拱跨宽、拱顶高与示意长度分清；几何值与统计值使用后端字段。

### 5.2 数值与证据

- 温度重建、均值、极值、区域比较和历史聚合由后端负责；前端做格式化、坐标吸附、展示与交互，不增加第二套业务计算。大模型负责理解和组织语言，不能凭语言生成一个温度结果。
- 拱外无定义、无测量带不报数、有可报告的场值沿用 `charts/pick.ts` 的判定。原始传感器读数、重建格点值、混合断面结果要有明确来源。
- `VolumePlane.measured` 表示该断面是否有实测支撑，不代表断面内任意格点都是传感器直接测到的值。助手和历史页不能把整张重建场写成“全部实测”。
- 摘要采用 `y_step=3` 的较稀采样，三维当前通常为 0.5m 间隔；跨页比较需记录并复用统计采样策略。不同网格得到的均值不能默认完全相同。
- 沿棚均温图的横轴是空间位置，历史趋势图的横轴是时间；两页要明确区分。`vmin/vmax` 是色标范围，不直接充当已验证的业务极值及其位置。
- 同一次展示、一次问答和一次历史快照，都应能追溯到数据源、数据时刻、模型和计算设置。缺少的元信息通过后续契约补齐，不能由前端猜。

### 5.3 建议统一的页面上下文

建议先对齐下列信息的含义，再决定用路由参数、组合函数还是服务端快照来传递。名称是讨论草案，当前接口未完整提供这些字段。

| 信息 | 用途 |
| --- | --- |
| 来源类型、来源标识和运行批次 | 区分实时演示源、上传数据集、已归档记录 |
| 数据时间、帧号或记录标识 | 回到用户询问或查看的那一刻 |
| 实际模型版本或成品指纹 | 确认答案和历史图使用的模型 |
| 几何版本、坐标和区域范围 | 让三页选中同一位置 |
| 网格、单调约束与统计采样策略 | 保证数值可比、可追溯 |
| 稳定快照标识 | 可选；服务端支持后用于固定一次分析对象 |

URL 适合放可校验的标识和筛选条件，不放完整体网格。共享逻辑集中实现，新增业务组件前先查看现有组件是否可扩展。

## 6. 并行协作和一致性检查

建议由一位成员维护外壳、令牌、共用类型和格式化；其余成员按页面交付纵向功能。接手前共同确认上下文和最小接口，涉及共用文件时同步变更说明，避免重复修改 `App.vue`、`copy.ts` 和 `types.ts`。

每页交付建议包含：功能范围和暂未实现项、接口及样例、真实数据或标注清楚的模拟数据、关键状态截图、验证结果和仍需讨论的问题。截图用于团队对齐视觉，不能证明 WebGL 交互和数值正确。

共同验收关注：

- 三页切换时顶栏、模式、导航、卡片、字体和颜色保持统一，直接刷新新页面也正确。
- 加载中、无数据、未准备、空结果、服务异常、旧数据仍在显示分别有清楚表达，失败不补成零。
- 所有查询可以定位到其数据时间和来源；图、数字、回答不混用不同帧或不同模型。
- 键盘可操作，焦点可见，禁用按钮有解释；长问题、长模型名、长错误文字不会撑破布局。
- 图表、三维和后台轮询按需运行；页面卸载后清理计时器、监听和请求状态。
- 共用语义和控件变更同步检查其他页面，而不是只改当前页面的样式。

建议复用或更新现有 `design/*`、`App.test.ts`、`router/router.test.ts` 和相关组件测试。部分守卫按源码文本和固定组件名单检查；扩展时维护它们表达的约定，避免为了通过新页面直接删除保护。
