# G 气象映射训练与完整外部气象预览

更新：2026-11-06。G/F 组合发布已接入，见 [发布与棚体配置](29-weather-model-publication.md)。

## 数据预览

数据导入没有移除光照或湿度：`load_dataset` 原本就要求 `bg_temp_C`、`bg_light`、`bg_rh_pct`。此前 `/api/dataset/preview` 只选择背景温度和 24 个棚内温度，造成只导入温度的错觉。

预览现在依次展示背景温度、背景光照强度、背景湿度，再展示 24 个棚内温度。新增可选列元数据 `unit`，温度为 ℃，湿度为 %；光照保留源数据口径，没有依据时不标为 lux 或 W/m²，不擅自换算。棚内湿度及质量标记不在此预览表范围。

## 训练页面

`/train` 增加“空间构场模型 F / 气象映射模型 G”两个阶段入口。F 原流程保留。G 可以配置名称、上线输入方案、算法、时间留出比例和随机种子：

- `full`：背景温度、光照和湿度；输出 24 个虚拟温度。
- `two`：上线只输入背景温度和光照，同时预测 F 所需的背景湿度；训练仍需真实背景湿度标签。
- ExtraTrees：树数量 16–300、深度 2–24、叶节点最少样本 1–20，默认 120 / 12 / 2。
- Ridge：训练段拟合 StandardScaler 与正则回归，默认 α=10。

当前选择一个算法与一组参数执行训练，并非 G 自动参数优选。两个版本分别训练：单时刻版、一小时历史版。输入只包含外部气象及其派生特征，24 路棚内温度仅作监督标签。

## 验证和成品口径

按时间先后划分前段训练、尾部验证，默认 80% / 20%，允许尾部 10%–40%。至少 80 个时刻；缺失或无效气象/标签会明确拒绝，不悄悄删行。历史特征仅用当前和过去的外部气象，遇到非连续 5 分钟间隔时冷启动，不跨缺口沿用历史。

保留尾部数据，不在出分后重新拟合全量，因此成品与成绩对应同一训练范围。结果提供两版本训练 MAE、留出 MAE/RMSE/R²、24 个测点明细及背景温度基线。两输入方案另报告背景湿度预测误差，单位为百分点。温度误差的 n 为留出时刻数乘 24，R² 为可计算测点的平均。

这些是当前数据集内部时间留出成绩。多次根据该验证段修改参数后，最终结论仍需要额外独立时段；不能把本页成绩当作跨地区、尺寸缩放或全空间实测精度。一小时版不保证比单时刻版更好，页面保留两者结果供比较。

## 服务与持久化

| Java 公共接口（仅 ADMIN） | 用途 |
| --- | --- |
| `GET /api/weather-training` | 当前数据集信息、最近 20 个 G 训练记录及当前执行任务 |
| `POST /api/weather-training/jobs` | 提交 G 配置；要求 `Idempotency-Key` |
| `GET /api/weather-training/jobs/{id}` | 查询进度、结果和成品摘要 |
| `POST /api/weather-training/jobs/{id}/cancel` | 请求取消，等待当前拟合阶段结束 |

Java 从服务端当前数据集生成快照，不采信浏览器传入的数据集头或任意路径；操作编号结合认证账号生成稳定任务 UUID。Python 内部路由 `/internal/v1/weather-training` 继续要求内部密钥，数据集身份、文件摘要和名称通过现有上下文协议校验。

计算记录及成品持久化在 `TFIELD_WEATHER_TRAINING_ROOT/<任务UUID>/`，统一启动默认 `backend/configs/weather-training`：

- `state.json`：数据来源、配置、状态、时间范围、验证结果和 SHA-256。
- `current.pkl`、`history.pkl`：已训练的 `WeatherNodeModel`，可用于现有气象模型包格式。

G 计算记录和成品由 Python 数据区保存，不会混入 F 模型库。管理员在训练结果下方选择已保存 F 并点击“组合并发布”后，由 Java 登记为 MySQL `weather_model` 发布记录，供棚体档案选择。正常页面不上传 pickle 或接收任意文件路径。

同一操作重试不重复训练，配置或数据摘要不同则拒绝复用操作编号；最多一项 G 同时执行。切页保持前端应用作用域中的进度与表单，刷新可从服务端恢复记录。更换账号销毁客户端缓存，更换数据集不把旧结果当作新数据结果。计算服务重启后，已完成成品保留，未完成任务明确标为失败，不偷偷重跑。内部活动检查包含 G，统一重启会等待正在执行的 G 任务结束或取消。

## 后续边界

G 训练、独立成品归档、G/F 组合发布和棚体配置链路已接通。训练完成后需由管理员明确组合发布，再绑定档案；不会自动发布实验模型或修改正式档案。

发布通过 G 任务 UUID 引用原成品，并校验来源、摘要及 F 模型库一致性。若将来把 G 任务业务记录迁入 MySQL，应添加明确迁移及恢复策略，不能令现有文件记录消失。
