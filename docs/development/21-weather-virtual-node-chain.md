# 外部气象 → 虚拟测点 → 冻结构场：离线原型与评估

日期：2026-11-04。

## 本轮实现

新增 `backend/src/tfield/weather_chain.py`，将独立训练的代表点预测模型与现有 `FieldPipeline` 串联。

- `WeatherFeatureSpec`：选择温度/光照或完整气象，以及是否使用过去一小时外部历史。
- `weather_features`：只读取外部气象与时刻；有历史时要求连续 5 分钟帧，使用 15/30/60 分钟滞后、滚动均值和变化量。不会读取棚内温度或湿度，也不读取未来天气。
- `WeatherNodeModel`：训练标签为每帧 24 个棚内温度，运行时输出 24 个虚拟温度。两输入方案还将背景湿度作为辅助标签预测，补齐旧第二阶段所需的背景湿度；不偷读测试湿度。
- `WeatherFieldChain`：仅接受时刻和外部气象，逐帧调用 `append_live_frame`。第二阶段必须已拟合/恢复，适配器不训练第二阶段；输出明确标记为 `virtual_weather_prediction`。

本轮不增加生产接口、前端入口、模型库记录或用户角色。原型用固定测点布局，并不支持任意棚型或尺寸缩放。页面若后续接入，必须将虚拟输入与实测来源分开标记。

## 数据与模型

- A：576 帧，第一阶段拟合。
- B：288 帧，第一阶段候选选择。
- C：444 帧，本轮后续时段开发对照。此前分析中已查看，不能称为新盲测。
- 第二阶段：只读复制当前已保存的模型 ID 3“模型B”，训练范围为 B，有可用二进制成品。本轮恢复该成品并保持树和 IDW 参数冻结。
- 原管线以 A 历史数据为加载种子，在 B/C 运行时只接外部气象生成的虚拟节点。种子属于管理员历史资料，不要求普通用户提供运行时棚内温度。

第一阶段预先比较 32 个候选：两种输入 × 有/无一小时历史 × 8 个配置（Ridge、ExtraTrees、多输出 XGBoost）。两个最终方案均由 B 选中二次特征 Ridge（alpha=1），都使用一小时外部历史；没有依据 C 继续调参。

## 本轮主要结果

下表为 C 时段，10,656 个点时刻评分对：

| 方案 | 第一阶段节点 MAE/℃ | 冻结构场原始节点 MAE/℃ | 默认约束后 MAE/℃ | 约束后 P95/℃ | 约束后最大误差/℃ |
| --- | ---: | ---: | ---: | ---: | ---: |
| 温度＋光照，背景湿度辅助预测 | 0.2975 | 0.2975 | 0.2986 | 0.8829 | 2.3420 |
| 温度＋湿度＋光照 | 0.3448 | 0.3448 | 0.3463 | 0.9432 | 2.3188 |

原始节点结果几乎复现第一阶段，是 IDW 的源点插值性质，不能解释为第二阶段验证了整个体积的真实性。节点处主要误差来自第一阶段，默认单调约束使本批 MAE 略增。两输入表现较好，不代表湿度对其他数据无价值。

对全部时刻的三个已有断面，预测输入场与真实输入参考场的平均绝对差异，C 上分别为 0.2505℃、0.3038℃。该数字是两个模型场之间的差异，不是全空间实测误差。

补充从 IDW 源排除三个同位置节点的检查，C 上两输入 MAE 为 0.3244℃，完整气象为 0.3461℃；这些位置在历史中已知，不声称新位置泛化。

## 复现文件与运行

本机完整归档：`outputs/model-evaluation-weather-chain-20261104/`。目录按既有规则忽略，包含实际数据与训练成品，不进入 Git。

- `protocol.md`：开始计算前确定的协议。
- `inputs/`：A/B/C、只读复制模型、外部气象 CSV。`external-weather-two.csv` 不包含湿度或任何棚内值。
- `models/`：全部候选、入选模型、冻结树摘要。
- `results/`：210,816 条逐点逐时刻预测、汇总、源隐藏检查、网格差异。
- `fields/`：按首帧/最大光照/最大节点误差/末帧规则去重后的 7 个全体积，每卷 37 个 y 切片，均有约束前后与真实输入参考。
- `plots/`：5 组 PNG 与 SVG 图。
- `process/source/`：实际使用的核心源代码快照；另保存环境、过程日志、输入哈希和验证记录。
- `report.md`、`report.html`：完整中文报告。
- `run_inference.py`：独立推理入口，只打开历史 A 种子、已保存模型和外部 CSV，不打开 B/C 棚内温度。

从项目根目录执行（本机使用 `D:/python/python.exe`）：

```powershell
# 只含温度/光照与时刻的文件，逐帧通过两阶段，输出节点预测
python -X utf8 outputs/model-evaluation-weather-chain-20261104/run_inference.py --schema two --weather outputs/model-evaluation-weather-chain-20261104/inputs/external-weather-two.csv --output outputs/model-evaluation-weather-chain-20261104/results/replay-two.csv

# 重新运行实验，复用已经拟合的候选；不会访问数据库
python -u -X utf8 outputs/model-evaluation-weather-chain-20261104/evaluate.py
python -X utf8 outputs/model-evaluation-weather-chain-20261104/make_report.py
python -X utf8 outputs/model-evaluation-weather-chain-20261104/finalize_archive.py
```

`capture_inputs.py` 只运行一次；其数据库事务只读，已存在输入快照时拒绝覆盖。其他机器复现需保留整个本机归档，并安装归档中的依赖版本。重新计算后应刷新文件摘要清单。

## 证据与边界

本轮实际逐帧运行 732 帧；过程验证 158 项通过；新增模块的 7 项边界测试通过。验证包括第二阶段不调用 fit、树摘要不变、输入摘要不变、批量/逐帧一致、未来数据不影响过去特征、测试湿度不影响两输入方案、重复/缺失输入不推进状态、误差传播恒等式、凸权重界和原 field_at 与批量网格一致。独立报告审计再次重算指标。

B 已用于选参，且第二阶段在 B 拟合。C 是同一采集批次、已经查看过的后续时段。源温度经过时间对齐，B/C 均为插值标记 1，没有原始逐点采样的独立验真；未验证真实天气 API、天气预报、其他季节、新棚或缩放。

现有节点精度证据不能替代体积真值，代表性场图只是模型对照。上线或形成正式精度结论前，应增加未参与开发的新时段和独立空间测点；部署时还需自动提供气象历史、输入口径检查和模型绑定。
