## 用户流程

1. 构建温度场，选择“人参生长阶段”。默认不推断阶段；阶段偏好按角色与账号保存于本机。
2. 点击“更新建议”，复用现有 AgriSeek 能力检查、固定快照、提交任务及查询任务接口。没有温度场或没有阶段时禁用按钮；不随定时气象更新自动请求模型。
3. 展示助手实际发布的建议、适用条件与待确认信息。失败、未配置、证据不足均显示实际状态，没有硬编码的农事结论兜底。
4. 点击“继续提问”打开 `/assistant?conversation=<UUID>`，读取原会话、原快照与作物阶段，下一轮沿用 `parent_run_id`。尚未生成建议时只预填人参及阶段，不自动提交。

阶段选择为出苗展叶期、现蕾开花期、果实成熟期、生育后期、采收及休眠期。术语参考吉林省农业农村厅[《人参非林地生产技术规程》](https://agri.jl.gov.cn/yw/bzcx/202503/P020250331524601663485.pdf)。具体阈值与操作条件由 AgriSeek 根据适用资料核验，前端不写死阈值，也不根据日期推断生长阶段。

## 快照、来源与权限

- `POST /api/assistant/snapshots` 新增可选的 `session_id`，只接受合法 UUID 与 `frame_index=0`。旧的空请求仍可绑定当前结果。卡片必须显式传入画布显示的构场编号，防止另一地点稍后完成构场时绑定错误结果。
- Java 仅允许读取当前账号拥有的已保存气象构场结果，并向 Python 传递原始外部气象、地区、模型档案、气象来源及照度转换信息。前端不能提交自己的温度场内容代替服务端结果。
- Python 将气象快照记为 `data_mode=external_weather`；已有文件回放快照保持默认 `replay`。外部温度、湿度、照度均作为独立事实保存，保留原始来源时刻。外部湿度缺失时不以预测棚内湿度补齐。
- 光照明确是辐射预报换算的近似照度，棚内点温与网格是模型估算。单棚原型沿长度均匀展开，未验证跨尺寸准确性；这些限制随快照进入助手上下文。
- 作物固定为人参；参龄、栽培方式、土壤墒情未知时不猜测。外部相对湿度不能代替棚内湿度或土壤墒情。诊断病害、设备设定或具体阈值仍需适用证据与现场条件。
- 使用现有助手用户命名空间和会话授权，不新增匿名接口、用户权限或模型凭据入口。凭据仍只在服务端配置。

## 流式接收大小误拦截修复

2026-11-14 用户实际任务 `78178cb6-137f-47d6-be8b-cfcfba253fae` 报 `model_stream_size`，界面显示“模型响应超过允许大小”。该任务已经进入模型和工具执行阶段，在第 4 次模型调用期间被接收器中止。原实现把每一条 SSE 文本行（包括重复 JSON 元数据、心跳、思考分片及正文）累计到同一个 512 KiB 限制，因此正常的短候选也可能因分片包装开销被提前拦截。该错误发生于接收阶段，不能据此判断候选是否能通过后续农事核验。

接收器现分别限制总传输行数据 8 MiB、单事件 256 KiB、实际合并的正文/思考/工具文本 512 KiB。未保留的思考内容也计入文本预算；原有工具参数长度、完整结束标记、调用结算、超时与任务总预算继续生效。工具执行需要完整流结算，候选发布仍须通过引用与数字核验。

增加正常大传输/小内容、UTF-8 文本与思考预算、超大单事件、心跳总量及完整 HTTP 模拟接收回归。37 项流式、原生思考、协议测试通过。完成与失败的诊断仅保存传输字节数、文本字节数、事件数及触发的限制类别，不保存模型原始思考或提供商响应正文。脱敏故障记录和修复说明存放于 `.local/agronomy-advice/stream-size-fix/`，本轮未额外请求真实模型或天气服务。
