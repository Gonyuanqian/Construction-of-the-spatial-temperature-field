# G/F 组合发布与棚体配置

更新：2026-11-06。

## 管理员操作

1. 在模型训练的“空间构场模型 F”中完成训练并保存成品。
2. 在“气象映射模型 G”中完成训练，或查看已有的已完成记录。
3. 在结果下方“发布与配置”填写气象模型名称，选择一个已保存的 F，点击“组合并发布”。单时刻 G 和一小时历史 G 一并包含，运行时按气象历史是否充分自动选择。
4. 前往棚体档案，选择档案，在模型配置中选择该气象模型并保存。已有页面可点击“刷新”获取新模型。
5. 用户在实时监测的“气象接入”窗口选择棚体配置，并输入气象来源省市/区县、时刻和外部气象，或导入五列演示 CSV。地区不决定模型；仅有一份启用配置时自动选用，多份时明确选择，见 [模型选用规则](31-region-independent-model-selection.md)。`full` 需要温度、湿度、光照，`two` 需要温度、光照。

训练与发布是两个明确动作。发布不会修改训练成绩、重新拟合模型、自动选用工作区 F 或自动切换正式棚体配置。页面列出该 G 的发布记录，支持停用和重新发布。停用后不再用于新构场，历史结果及配置快照保留。

## 接口与责任

| 接口（仅 ADMIN） | 用途 |
| --- | --- |
| `GET /api/weather-training/field-models` | 列出数据库中已经保存二进制 F 成品的记录；不依赖当前数据集 |
| `GET /api/weather-training/jobs/{id}/deployments` | 查询该 G 的组合发布记录 |
| `POST /api/weather-training/jobs/{id}/publish` | 请求 `{name,field_model_id}`，要求 `Idempotency-Key`；组合、登记并发布 |
| `PATCH /api/admin/weather-models/{id}` | `{status: PUBLISHED 或 DISABLED}`，复用既有校验与状态流程 |

Java 从 MySQL 读取所选 F 成品及摘要。浏览器只提交 G 任务 UUID、F 编号和名称，不能上传 pickle 或指定模型文件路径。Python 内部 `/internal/v1/weather-training/jobs/{id}/package` 要求服务密钥，只从持久化 G 任务中取出已完成成品，校验 SHA-256、G 输入方案、24 点输出、两种历史特征版本、F 成品格式及特征列。

完整模型包先写入专用临时目录并校验，再以原子目录重命名进入部署目录。包中保存 G 任务、原数据集身份和摘要、G/F 文件摘要及名称，供后续追溯。该步骤检查成品完整性与协议兼容，**不生成或宣称新的泛化精度成绩**。

Java 再核对包中的 F 与模型库成品一致，事务写入 `weather_model`，状态为 `PUBLISHED`。沿用现有表及 `metadata_json`，无需新增数据库迁移。G 原始任务及成品仍保留在 Python 数据目录，组合包保存在 `TFIELD_WEATHER_MODEL_ROOT`；业务发布记录保存于 MySQL。

## 重试与边界

- 操作编号结合当前管理员生成稳定包 UUID。相同操作重复提交恢复原包及业务记录，不重复训练或生成新的部署；换 G、F 或名称复用同一编号时拒绝。
- 已停用记录遇到原发布请求重试时维持停用状态，需要管理员显式重新发布。
- 前端在应用工作区中保留发布操作编号；返回页面从服务端恢复发布记录，避免重复创建相同名称、F 的组合。跨账号清理客户端工作区。
- G 未完成、缺少/损坏成品、F 只有参数没有成品、特征协议不符时返回明确错误。G 成品训练时使用的留出成绩不变。
- 已完成的旧 G 训练记录可直接组合发布，不要求重新训练，也不要求它仍是当前数据集。
- 模型仍适用于既定棚型和固定尺寸；本次不开放棚体几何缩放或天气接口自动采集。

## 验证

- Python：实际训练 G，组合精确 F 成品，在 `two`、`full` 两方案下分别以单帧和 13 帧历史构建 37 片三维场；禁止重新拟合 F/G。覆盖重启恢复、幂等、损坏成品和内部权限。
- Java：H2 隔离库验证持久化、档案显式绑定、停用、重试、摘要及参数校验；MVC 验证管理员边界和不依赖当前数据集。
- 前端：发布前选择、返回恢复、请求失败重试、任务切换时忽略旧回执、停用/发布、无 F 引导及棚体页面刷新配置。

测试没有发布实验模型到正式档案；正式模型由管理员按上述流程选择。
