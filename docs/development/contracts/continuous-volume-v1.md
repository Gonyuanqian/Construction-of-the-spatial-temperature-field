# 连续空间温度场与坐标查询 v1

更新：2026-10-29。训练与实时三维视图共用本实现。

## 数据与计算

- 沿用 `field_at` 生成的 x/z 网格与沿 y 的重建切片，默认间隔 0.5 m、0–18 m。
- 任意坐标在其所在单元内做三线性插值。先取得与画布一致的、已施加竖直约束的角点温度，再插值；不直接调用未经该约束处理的单点预测替代画布值。
- 只使用非零权重角点。精确命中格点时保持该格点原值，不要求零权重邻点有效；任何实际参与的角点缺失或属于无测量带时，不跨越它补数。
- 拱外、无测量带、有效邻点不足和范围外分别处理，不能统一填零或吸附到边界。
- 断面间为重建估计值；连续表示与更密采样不增加真实观测信息。原有两端沿用最近可用断面的算法边界不变。

## 接口

| 接口 | 上下文 |
| --- | --- |
| `GET /api/field/point` | 当前训练数据与工作区模型 / 未保存结果 |
| `GET /api/live/point/{n}` | 指定实时会话绑定的源副本、模型及已播放帧 |

必填 `x`、`y`、`z`。训练接口支持 `t_index`；两条接口均支持 `preset`、`monotonic`、`y_step`、`y_min`、`y_max`，与整卷接口默认值相同。实时接口还携带 `session_id`，由 Java 校验会话，拒绝过期引用及尚未播放的帧。

整卷返回新增 `field_ref`；查询传入 `expected_ref`。数据集、模型或结果配置变化导致引用不一致时返回 409，提示重新构场。它是来源一致性校验，不是访问凭据。

响应示例（温度仅示意）：

```json
{
  "x": 1.025, "y": 6.2, "z": 0.675,
  "time": "2026-07-27 12:00:00", "t_index": 0,
  "kind": "value", "value": 29.52, "method": "trilinear",
  "measured_plane": false, "shed": null, "max_measured_z": 1.1,
  "field_ref": "来源摘要", "note": "同一份约束后三维网格内的重建值"
}
```

`kind` 为 `value`、`outside`、`unmeasured` 或 `unavailable`；后三种的 `value` 为 null。范围外或非有限坐标返回 400。`measured_plane` 只表示坐标位于布设测点的断面上，不意味着该位置就是传感器实测点。实时响应还附带 `frame` 与 `live`，继续使用帧号到管线时间的映射。

## 显示与交互

- `volumeGrid.ts` 将温度和有效性分开打包为三维纹理，坐标顺序为 x/z/y；`volumeMaterial.ts` 在 GPU 内先插值温度，再按共用色标着色，沿射线累积显示。
- 默认立体态，训练与实时页面均可切换切面态；切换不重新请求温度场，不重置剖切刀、示意长度或相机方向。
- 剖切刀支持 0.01 m 步进，不再绑定切片间隔。体绘制入口随刀口移动，鼠标可以查询切片之间的剖切面。
- 立体拾取定位第一个有效表面 / 剖切面坐标，前端不计算读数；180 ms 防抖后请求后端。体内点可直接输入坐标，屏幕上的一次点击不能单独确定体内深度。
- 请求携带画布本身的时刻、网格参数与来源引用；换帧、换会话和卸载使旧响应失效。钉住点按原坐标保留并在新帧重新取值。
- 高 DPI 下限制立体态绘图分辨率，避免每像素多次采样导致负担倍增。硬件性能仍需在目标机器验收；无 WebGL 时保留已有不可用提示和二维入口。

## 验证与运行

针对性回归包括解析线性场的三轴插值、精确节点、缺失角点、范围拒绝、真实约束后整卷与查询对拍、实时帧时间映射、来源变化拒绝，以及连续拾取、剖切、钉住和过期响应丢弃。

新增 API 需要同时重启 Python 与 Java，Vite 开发页面自动更新；8080 部署页面还需重新构建发布前端。当前没有重新完成目标浏览器的 WebGL 视觉和性能验收。
